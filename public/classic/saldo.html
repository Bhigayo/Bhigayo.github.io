Case study

Saldo

A personal finance app that answers one question: how much can I safely spend until payday?

Role
Sole developer
Type
Personal project
Platform
Web and phone (PWA)
Status
Live
Try the app ↗ View the code ↗

The problem

Banking apps tell you your balance, but your balance isn't what you can spend. Rent, bills and the money you mean to save are already spoken for, and payday might be three weeks away.

I wanted one number that takes all of that into account, and a daily figure that tells me whether today's spending keeps me on track.

What it does

  • Safe to spend and a daily allowance. Income, minus bills and the savings target, minus what's been spent this month, spread across the days until payday.
  • Bills and subscriptions. Monthly, weekly and yearly bills are converted to a monthly cost. The Subscription Guardian flags free trials before they start charging.
  • Category budgets and savings goals. Overspent categories turn red, and each savings goal shows how much to put away every month to hit its deadline.
  • "Can I afford this?" Type in a price and see whether it fits before you buy.

Key decisions

The money maths is tested

All the calculations live in small functions with no UI code, covered by 36 unit tests. GitHub Actions runs them on every push, and nothing is deployed if one fails.

Dates are treated as UK days

JavaScript reads "2026-10-07" as midnight in UTC, which is 1am in summer. The tests run in UK time and cover paydays in short months and the clocks changing.

Your data stays on your device

There are no accounts and no server. Everything is saved in the browser, which keeps people's finances private and the app free to run.

It works like a phone app

A web app manifest and a service worker let it be added to a home screen and open offline after the first visit.

What testing found

Writing tests for the existing code turned up real bugs:

  • An off-by-one day. Trial reminders could show one day too many during British Summer Time. A test now pins the exact case.
  • A button that did nothing. The edit window was written in the wrong place, so editing a transaction never opened it.
  • Broken values getting saved. Forms accepted non-numbers for income and bills, which then broke every total.
  • Invisible progress bars. The budget bars used a colour that didn't exist in the stylesheet.

None of these would have shown up from looking at the code. Each needed a test or a real check in the browser.

What's next

Export to CSV, a monthly summary and optional reminders before bills are due.
